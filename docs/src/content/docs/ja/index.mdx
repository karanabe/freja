  <section class="landing-intro" aria-labelledby="landing-intro-title">
    <p class="landing-eyebrow">interactiveなデフォルト</p>
    <h2 id="landing-intro-title">判断経路を隠さず、ローカル通信を検査する。</h2>
    <p>localではTUI、active enforcement、上限付きinteractive HTTP decisionから始めます。headless運用はHookを無効にしますが、enforcementは有効なままです。TLS interception、外部公開、payload captureは引き続き明示opt-inです。</p>
  </section>

  <div class="landing-principles" aria-label="Frejaの設計原則">
    <section>
      <span aria-hidden="true">01</span>
      <h3>すべての動作を説明する</h3>
      <p>ポリシー世代、一致ルール、観測した事実、最終動作を各Decisionに記録します。</p>
    </section>
    <section>
      <span aria-hidden="true">02</span>
      <h3>すべての資源に上限を設ける</h3>
      <p>接続、body prefix、channel、timeout、pause flow、証明書cacheに明示的な上限があります。</p>
    </section>
    <section>
      <span aria-hidden="true">03</span>
      <h3>証跡をローカルに保つ</h3>
      <p>監査レコードをredact・hash chain化し、必要なら署名して、新しいポリシーでreplayできます。</p>
    </section>
  </div>

      <p>組み込み設定を検証し、引数なしでFrejaを起動して、loopback proxy経由でHTTPリクエストを1件送ります。</p>
