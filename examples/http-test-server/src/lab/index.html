Before sending: origin, proxy and pause
  1. Run this origin and Freja in separate terminals. Use examples/config/tui/freja.interactive.toml: TUI + Enforce + Interactive, HTTP only. This lab explicitly allows loopback upstreams.
  2. Set the browser’s HTTP proxy to 127.0.0.1:8080 and remove loopback/localhost bypasses. Open this page over http://. Browser bypass rules vary; check the TUI instead of trusting the setting alone.
  3. The page GET and its local script/style requests can pause too. Select them in Freja and press c to continue. The 30-second decision timeout applies to each paused request.
  4. Give each attempt a new case label. It helps find the request; Freja’s TransactionId is the identity. Repeat may send the same case again under a new transaction.

Reject r
An explicit operator reject occurs before forwarding. Match the rejected transaction in the TUI and confirm there is no corresponding origin request. An HTTP error alone does not prove reject or non-arrival.
Repeat Shift+R, then s
On a paused row, Shift+R continues the original unchanged and creates a Repeat workspace. Sending that draft creates a new transaction and an additional origin request; it does not pause again. Read its latest response on Repeat, not as a new response to this browser form.
If the result is missing or rejected
  • Waiting: inspect Freja for a pause. The browser cannot detect that state. Its 45-second wait limit exceeds the sample’s 30-second decision timeout; cancelling that wait does not prove non-arrival.
  • 400 / 413 / 415 from the lab: the origin received an invalid, oversized or unsupported form. Read the error and the actual received bytes when available. Decoded fields are unavailable if the edit broke the form.
  • Reject or decision timeout: check the TUI’s reason and origin terminal. Do not treat an Observe policy deny as an operator reject or actual block.
  • Origin stopped / network error: arrival is unknown from this page. Check both terminals and restore the origin. Inputs stay here; returning to them does not retry.
  • Echo but no matching Freja transaction: the browser may have bypassed the proxy. Freja traversal is unverified. A direct request is a useful control, not a passing proxy test.
